Parker's Diamond Detailing

The website and back office for a mobile auto-detailing business.

My son runs a detailing business around Richmond. I built the site that brings in his customers and the system behind it, and I keep it running.

  • No framework and no build step. The front end is plain HTML, CSS and JavaScript, so there is very little to break and nothing to upgrade on a schedule.
  • One server, everywhere. The same Lambda handler runs in production and on my laptop, with AWS swapped for local stand-ins, so what I test is what ships.
  • Deploys by branch. A push to QA goes to QA and a push to main goes to production, after the Jest and pytest suites pass.
  • A phone-first customer book for jobs and before/after photos, with an outbox that holds changes when the signal drops. It is in testing with the one person it was built for.
  • More than 750 commits since March 2023, and no secret in any of them.

Janell's Run

An iOS app for tracking races, with exactly one target user.

My wife runs races and wanted her results, PRs and history in one place. She uses it, files feedback from inside the app, and I ship the fixes.

  • Zero third-party dependencies. About 3,600 lines of Swift, with unit tests that run on every pull request.
  • Her data stays hers. It syncs through her own private iCloud database, and the app only ever reads from Health.
  • Imports years of race history from CSV files and Athlinks.
  • Feedback becomes a GitHub issue through a small Cloudflare Worker. It is rate-limited, and it strips names before anything reaches the public repo.

AgentCafe

The cafe for agents.

AI agents browse a Menu of real-world services, show a Passport proving a human authorized them, and place orders. The Cafe sits in the middle and handles authorization, consent and audit, so an agent never sees a backend URL or a credential.

  • Two tiers of permission. An agent can ask for read access by itself. Anything that writes needs a human to approve it with a passkey.
  • Checked twice on every order: the human's Passport and the company's own policy, with budget, duration and scope limits.
  • A tamper-evident audit log, hash-chained with SHA-256.
  • An onboarding wizard that turns a company's OpenAPI spec into a published service.
  • 405 tests and a pylint score of 10.00.

Human Memory

Memory for AI, owned by humans.

An API that gives AI agents persistent, structured memory across sessions. The human it belongs to can see everything, decide which agent gets which access, and delete any of it.

  • Agents can store and search. Only the human can delete.
  • Scoped access tokens, shown once and never stored in plaintext.
  • Every query is isolated by namespace at the storage layer, and the audit log never contains the stored values.
  • Full-text search on SQLite FTS5, and passwordless sign-in by magic link.
  • 474 tests.

How I work

Finish the unglamorous parts

Tests, CI, rate limits, audit logs, a privacy policy that matches what the code does. A project isn't done when the demo works.

Keep it small enough to hold in your head

No framework where plain HTML will do. No dependency I can't justify. When something breaks, I want to already know where to look.

Build for one real person first

A business owner on his phone in a driveway. A runner checking her PRs. I'd rather get one person's actual complaints than guess at what a thousand might want.

Know when to stop

I shelved two projects I liked because the demand wasn't there. Then I took production down, revoked the keys and backed up the data, instead of leaving it to rot.
